# Промпт для генерации отчёта по лабораторной работе

Исследуй папку указанной лабораторной работы (например, lab1 или lab2). В ней находятся файлы заданий task1, task2, ..., task_itog (например, task1.js в lab1; в lab2 — task1.html, а для заданий с вёрсткой дополнительно файлы стилей taskN.css). Файлы могут лежать прямо в папке лабораторной работы или в подпапках (task1, task2, ..., task_itog). Изучай их строго по порядку: task1, task2, ..., task_itog. Файл отчёта сохраняй в папке лабораторной работы — lab1/report.md, lab2/report.md и т.д.

**Заголовок отчёта:**
- Начинай с заголовка «# Лабораторная работа №N», где N — номер лабораторной работы.
- Сразу под ним добавь строку с темой, номером варианта и словами «Отчёт по проделанной работе», например: «HTML и CSS. Вариант 04. Отчёт по проделанной работе.»

**Требования к описанию:**
- За основу описания каждого задания бери TODO-описания из файлов.
- Тему раздела бери из строки «ЗАДАНИЕ №N: <тема>» в шапке файла задания.
- В начале раздела пиши описание в стиле лабораторного исследования: что изучено, использовано, применено. Разделяй смысловые блоки этого описания абзацами (пустой строкой).
- Выводы не оформляй отдельным подзаголовком и не пиши списком. После листингов и рисунков задания добавляй 1–2 абзаца с выводами, написанными связными предложениями. Включай в них всё, что в комментариях TODO задания указало оформить «в выводах» (например: особенности языка, типы данных, результаты прогнозов и их объяснения).
- Названия тегов, свойств, классов и значений оформляй обратными кавычками: `border-box`.
- Пиши кратко, без лишнего описания.
- Вместо стрелок «→» используй «=>». Вместо длинного тире «—» используй более короткое тире «–». Правило относится только к твоему тексту.

**Форматирование заголовков и ссылок:**
- Разделяй задания заголовками (## Задание N. <тема>, для итогового — ## Итоговое задание).
- Заголовок листинга оформляй как: «**Листинг N - Задание №N (<имя файла>)**».
- Если в задании несколько файлов, делай отдельный листинг на каждый; нумерация листингов сквозная по всему отчёту.
- После заголовка листинга вставляй код этого файла.
- Перед каждым листингом оставляй ссылку-описание в формате: «На листинг N показано: ...» (без скобок, кратко перечисли, что именно показано на листинге).

**Скриншоты (рисунки):**
- Изображения в отчёт НЕ вставляй — вместо них пиши подписи.
- На каждое задание должен быть РОВНО ОДИН рисунок в формате: «Рисунок N - Результат выполнения программы <имя файла>», где N — сквозной порядковый номер рисунка в отчёте, начиная с 1, без точек. Если в задании два файла, перечисли их через запятую: «Рисунок 3 - Результат выполнения программы task3.html, task3.css».
- Рисунок размещай после листингов задания и перед выводами.
- Для JS-заданий: если в коде есть закомментированные строки с пометкой `// err` (ошибки доступа к переменным вне области видимости), добавь дополнительные рисунки со сквозной нумерацией, продолжая счёт: «Рисунок N - Ошибка выполнения программы <имя файла>».
- В тексте описания добавляй ссылки на эти рисунки: «На рис. N показана ошибка ...». Ссылки на рисунки оформляй сокращением «рис. N», без фразы «см. рисунок».

**В конце отчёта:**
- Добавь раздел «## Заключение» с краткими итоговыми выводами по всей лабораторной работе. Заключение тоже пиши связными предложениями, без подзаголовков и без списков.

**Работа с файлами заданий:** файлы заданий не изменяй без прямой просьбы пользователя. Если нашёл отклонения от ТЗ или ошибки — сначала перечисли их пользователю и дождись указаний. Отчёт описывай по фактическому состоянию файлов.

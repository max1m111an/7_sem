# Промпт для генерации отчёта по лабораторной работе

Исследуй папку указанной лабораторной работы (например, lab1 или lab2). В ней находятся файлы заданий task1, task2, ..., task_itog (например, task1.js в lab1; в lab2 — task1.html, а для заданий с вёрсткой дополнительно файлы стилей taskN.css). Файлы могут лежать прямо в папке лабораторной работы или в подпапках (task1, task2, ..., task_itog). Изучай их строго по порядку: task1, task2, ..., task_itog. Составь отчёт по проделанной работе.

**Требования к описанию:**
- За основу описания каждого задания бери TODO-описания из файлов.
- В начале раздела пиши описание в стиле лабораторного исследования: что изучено, использовано, применено. Разделяй смысловые блоки этого описания абзацами (пустой строкой).
- Выводы не оформляй отдельным подзаголовком и не пиши списком. После листинга и рисунков задания добавляй 1–2 абзаца с выводами, написанными связными предложениями. Включай в них всё, что в комментариях TODO задания указано оформить «в выводах» (например: особенности языка, типы данных, результаты прогнозов и их объяснения).
- Код в отчёт НЕ вставляй — вместо него используй слово «Листинг N» (плейсхолдер).
- Пиши кратко, без лишнего описания.
- Вместо стрелок «→» используй «=>». Вместо длинного тире «—» используй более короткое тире «–».

**Форматирование заголовков и ссылок:**
- Разделяй задания заголовками (## Задание N. <тема>, для итогового — ## Итоговое задание).
- Заголовок листинга оформляй как: «**Листинг N - Задание №N**».
- Перед листингом оставляй ссылку-описание в формате: «На листинг N показано: ...» (без скобок, кратко перечисли, что именно показано на листинге).

**Скриншоты (рисунки):**
- Скриншоты терминала с демонстрацией исполнения программы НЕ вставляй картинками — вместо них пиши ссылки-подписи.
- На каждое задание должен быть РОВНО ОДИН рисунок в формате: «Рисунок N - Результат выполнения программы <имя файла>».
- Если в коде есть закомментированные строки с пометкой `// err` (ошибки доступа к переменным вне области видимости), добавляй дополнительные рисунки с сквозной нумерацией: «Рисунок N - Ошибка выполнения программы <имя файла>».
- В тексте описания добавляй ссылки на эти рисунки: «На рис. N показана ошибка ...». Ссылки на рисунки оформляй сокращением «рис. N», без фразы «см. рисунок».

**В конце отчёта:**
- Добавь раздел «## Заключение» с краткими итоговыми выводами по всей лабораторной работе. Заключение тоже пиши связными предложениями, без подзаголовков и без списков.

**Дополнительно:** если в коде есть отклонения от ТЗ или ошибки — при возможности исправить код согласно требованиям, а затем описывать отчёт в соответствии с реальным исправленным кодом и его фактическим выводом (файл отчёта создавай в папке лабораторной работы — lab1/отчёт.md, lab2/отчёт.md и т.д.).

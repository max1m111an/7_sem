# Спецификация приложения «Игра «Жизнь»» (клеточный автомат)

Документ предназначен для передачи в opencode / LLM-агента как ТЗ на развитие
проекта. Формулировки — императивные, требования — проверяемые.

---

## 1. Общее описание

**Название:** Игра «Жизнь»
**Тип:** десктопное приложение — клеточный автомат с GUI.
**Язык:** Rust (edition 2021).
**GUI:** `eframe` + `egui`.
**Назначение:** вариант игры «Жизнь» со своими правилами: два вида клеток —
**Добыча** и **Хищник** — с правилами рождения, гибели и межвидового
взаимодействия, на замкнутом поле (торе), без параметров, влияющих на правило.

**Ключевые требования:**
- Одно правило — «Хищник и добыча» (§4), локальное и детерминированное;
  обновление синхронное: все клетки читают старое состояние, пишут в буфер
  `next`.
- Два вида живых клеток: у каждого свои правила рождения/гибели, плюс
  правила межвидового взаимодействия (съедание и голод).
- Поле замкнуто: соседи берутся с заворотом через край.
- Полное отделение ядра симуляции от UI (ядро не зависит от egui).
- Минимальный интерфейс: canvas, пуск/пауза, один шаг, очистка, кисть вида,
  случайное поле, скорость, счётчики. Ничего больше.
- Старый код колонии (ресурсы, стресс, конструкции, антиклетки) остаётся в
  репозитории как справочный, **в игру не вызывается** и из интерфейса
  удалён. Его тесты обязаны оставаться зелёными.

## 3. Модель данных

### 3.1. Клетка

```rust
pub enum CellState {
    Empty,
    Citizen,
    Construction,
    Overlap,
    AntiCell,
}

/// Вид живой клетки игры «Жизнь».
pub enum Species {
    Prey,      // Добыча
    Predator,  // Хищник
}

pub struct Cell {
    pub state: CellState,
    pub kind: Option<ConstructionKind>,
    pub construction_id: Option<u32>,
    pub citizen: Option<CitizenData>,
    pub frozen: Option<CitizenData>,
    #[serde(default)]
    pub species: Option<Species>,   // вид живой клетки; None у мёртвых
}

impl Cell {
    pub fn empty() -> Self;
    /// Живая клетка «Жизни»: Citizen с видом Prey.
    pub fn alive() -> Self;
    /// Живая клетка указанного вида.
    pub fn with_species(species: Species) -> Self;
    /// true, если клетка жива в игре «Жизнь».
    pub fn is_alive(&self) -> bool;   // state == CellState::Citizen
    pub fn is_regular(&self) -> bool; // Citizen | Construction | Overlap
    pub fn is_occupied(&self) -> bool;
}
```

Варианты `CellState` **не добавлять**: старые тесты завязаны на текущий
состав. Вид — это отдельная метка `Cell::species`: игра живёт двумя
состояниями `Citizen` (живо) и `Empty` (мертво), а живая клетка несёт ровно
один вид, мёртвая — `None` (инвариант, который поддерживает `Life`).

### 3.2. Сетка и тор

```rust
pub struct Grid {
    pub width: usize,
    pub height: usize,
    pub cells: Vec<Cell>,
}

impl Grid {
    pub fn new(width: usize, height: usize) -> Self;
    pub fn idx(&self, x: usize, y: usize) -> usize;
    pub fn xy(&self, idx: usize) -> (usize, usize);
    pub fn get(&self, x: usize, y: usize) -> &Cell;
    pub fn set(&mut self, x: usize, y: usize, cell: Cell);
    pub fn neighbors4(&self, x: usize, y: usize) -> impl Iterator<Item = (usize, usize)>;
    pub fn neighbors8(&self, x: usize, y: usize) -> impl Iterator<Item = (usize, usize)>;
    pub fn cells_in_radius(&self, x: usize, y: usize, r: usize) -> impl Iterator<Item = (usize, usize)>;
    pub fn swap(&self, a: usize, b: usize);
}

/// Оборачивает `v + delta` в `[0, len)`; `len == 0` возвращает 0.
pub fn wrap(v: usize, delta: isize, len: usize) -> usize;
```

Соседи по граням и диагоналям **заворачиваются** через край: поле — тор,
левая граница соединена с правой, верхняя с нижней. Дубликаты не допускаются:
если смещение ведёт к уже встреченной клетке, она пропускается.

### 3.3. Движок игры

```rust
pub struct Life {
    pub grid: Grid,
    pub generation: u64,
    pub alive: usize,          // живых всего; всегда == prey + predator
    pub prey: usize,           // живых вида «Добыча»
    pub predator: usize,       // живых вида «Хищник»
    seen: HashMap<u64, u64>,   // приватная: отпечаток мира -> поколение первого появления
    pub cycle: Option<u64>,     // Some(длина цикла) — повтор отпечатка, App ставит паузу
}

impl Life {
    pub fn new(width: usize, height: usize) -> Self;
    pub fn step(&mut self);                       // одно поколение правила + ловля цикла
    pub fn clear(&mut self);                      // всё мертво, generation = 0
    pub fn randomize(&mut self, density: f32);    // thread_rng
    pub fn fill(&mut self, density: f32, rng: &mut impl Rng); // то же с явным ГСЧ
    pub fn set_cell(&mut self, x: usize, y: usize, species: Option<Species>); // вид или смерть
    pub fn set_alive(&mut self, x: usize, y: usize, live: bool); // true -> Prey
    pub fn resize(&mut self, width: usize, height: usize);    // центрирование + обрезка
    pub fn forget_cycles(&mut self);              // пустая история, cycle = None
}
```

`PREDATOR_SHARE = 0.2` (`life.rs`) — доля хищников среди живых клеток при
случайном заполнении. Константы правила (`PREY_BORN`, `PREY_MIN`/`PREY_MAX`,
`PREDATOR_GROUP`) — в начале `life.rs`.

## 4. Правило

Одно поколение — синхронный переход. Все клетки читают состояние прошлого
поколения и пишут в новый буфер, который подменяет сетку атомарно.
`prey8`/`predator8` — соседи вида среди N8, `prey4`/`predator4` — среди
ближнего кольца N4; всё считается по старому поколению.

```rust
match old(x, y).species {
    None if prey8 == 3 && predator4 == 0              => Prey,    // B3
    None if predator8 >= 2 && prey4 >= 1              => Predator,// стая у добычи
    None                                              => None,
    Some(Prey) if predator4 >= 1                       => None,    // съедена
    Some(Prey) if prey8 < 2 || prey8 > 3               => None,    // недо-/перенаселение
    Some(Prey)                                         => Prey,    // S23 среди своих
    Some(Predator) if prey4 >= 1                        => Predator,// сыт
    Some(Predator) if predator8 >= 2                    => Predator,// стая держится
    Some(Predator)                                     => None,    // голод
}
```

- **Добыча** живёт по классическому B3/S23 среди своих, но мгновенно гибнет
  от хищника в N4 и не рождается подле него.
- **Хищник** рождается только группой (≥2 хищников в N8) и только рядом с
  добычей (N4); выживает, пока рядом есть добыча (N4), а натощак держится,
  пока рядом ≥2 хищников (стая). Одинокий хищник без добычи
  гибнет от голода на следующем же шаге.
- Детерминизм обязателен: при равных условиях ответ один, ГСЧ в `step` нет.
- `generation += 1` на каждом шаге, включая пустое поле.
- `alive`, `prey`, `predator` пересчитываются по факту, а не прибавляются.

Больше условий остановки нет: ресурсов, стресса, конструкций и антиклеток
нет.

### 4.1. Детекция цикла: повтор отпечатка

Конечный мир обязан повториться, и повтор — пауза (Game Over):

- Каждое поколение хэшируется (`DefaultHasher` по битам `is_alive` и тегу вида
  клетки) и запоминается в `Life::seen` вместе с номером поколения.
- Если отпечаток уже встречался — `cycle = Some(текущее поколение − первое
  поколение с этим отпечатком)`, то есть длина цикла в поколениях.
- История **сбрасывается** (`forget_cycles`) при `clear`, `fill`/`randomize`,
  `set_cell`/`set_alive` (только при реальном изменении), `resize` (только при
  реальной смене размера) — любая правка мира начинает новый отсчёт.
- При повторе отпечатка игра **ставится на паузу** (`App::stop_on_cycle`
  выставляет `running = false` в `advance`). `cycle` не сбрасывается само.
- **Продолжить:** `Пуск` или `Шаг` просто продолжают шагать по тому же циклу
  (игра встанет снова только после правки мира или ручной паузы).
- Пустое поле циклится на первом же шаге (`cycle = Some(1)`, `alive == 0`) —
  это вымершая колония.
- Статус-бар показывает `life.cycle` напрямую (не из `App::message`)
  нейтральным цветом, поэтому надпись исчезает сразу, как только игрок правит
  мир.

## 5. UI

### 5.1. Окно

- Заголовок: `Игра «Жизнь»`.
- Размер по умолчанию: 960×600, минимум 780×500.
- Панели:
  - **Сверху** — тулбар (`panels::toolbar`).
  - **Снизу** — статус-бар (`panels::status_bar`).
  - **Центр** — canvas на всю оставшуюся область, `Frame::none()`.

### 5.2. Тулбар

Всё в одну строку:

- `Пуск` / `Пауза` — переключает `App::running`; при старте таймер и
  накопитель тиков обнуляются. После Game Over `Пуск` продолжает шагать по
  найденному циклу.
- `Шаг` — ставит паузу и делает ровно одно поколение.
- `Очистить` — ставит паузу (`running = false`), `Life::clear()`, сброс кэша
  текстуры и сообщение.
- Секция `Кисть:` — два цветных `SelectableLabel` («Добыча» `#000000`,
  «Хищник» `#D32F2F`) переключают `App::brush: Species`; hover — «ЛКМ рисует
  выбранным видом, ПКМ стирает».
- Числовое поле `Заполненность` (`DragValue`, 0.00..=1.00, шаг 0.01) и кнопка
  `Случайно` — `Life::randomize(density)` + сообщение.
- Числовое поле `Поколений в секунду` (`DragValue`, 1..60, шаг 1) —
  `App::ticks_per_second`.

Ползунков в интерфейсе нет: оба числа меняются перетаскиванием и вводом с
клавиатуры. Больше в интерфейсе нет ничего: нет панелей кистей (кисть —
две кнопки внутри тулбара), нет штампов, нет параметров правила, нет
сохранений и загрузок.

### 5.3. Стус-бар

`состояние | поколение N | добыча N | хищников N | сетка W×H | клетка N px`
плюс `App::message` светло-красным, если он не пуст.

Поверх сообщения, пока `life.cycle == Some(_)`, нейтральным цветом рисуется
надпись: `цикл N поколений`, а если `alive == 0` — `колония вымерла`.
Надпись берётся из `life.cycle` и `life.alive`, а не из `App::message`,
поэтому гаснет сама, как только игрок правит мир.

### 5.4. Canvas и зум

- Размер клетки — поле `Canvas::cell_px: usize`, диапазон `MIN_CELL_PX..=
  MAX_CELL_PX` (1..=32), по умолчанию `DEFAULT_CELL_PX = 14`. Экспорт:
  `pub use crate::sim::{MAX_CELL_PX, MIN_CELL_PX, MAX_TEXTURE_SIDE}`.
- **Зум — Ctrl + колесо.** `steps_from_ctrl_wheel` берёт `raw_scroll_delta`
  только при зажатом Ctrl (обычное колесо ничего не делает), накапливает
  дробный ход в `scroll_accum` и отдаёт целые шаги по 50 px. Шаги применяет
  `Canvas::zoom_by` с клампом к 1..=32.
- Зум **меняет размер сетки**: при смене `cell_px` вызывается
  `grid_dims_for(cell_px, area_w, area_h)` → `Life::resize(w, h)`, старое
  содержимое центрируется, лишнее по краям обрезается. Подгонка выполняется
  только когда `fitted_zoom != Some(cell_px)` — на ресайзах окна мир не
  обрезается, картинка просто растягивается (`fit_to_exact_size`).
- Текстура — одна `ColorImage` `(W*cell_px) × (H*cell_px)` под `TextureHandle`
  (`egui::TextureFilter::Nearest`, `ClampToEdge`).
- **Dirty region:** цвета сетки хранятся в `Canvas::prev`; на каждом кадре
  считается bounding box изменившихся клеток и перекрашивается только он.
  Пауза без правок не создаёт никакой работы для GPU.
- Сторона текстуры не больше `MAX_TEXTURE_SIDE = 2048` — предел GPU
  (`grid_dims_for` это гарантирует при любом зуме).
- **Ввод:**
  - ЛКМ — поставить клетку вида `App::brush`;
  - ПКМ — стереть клетку;
  - перетаскивание — линия по Bresenham, без пропусков; состояние перетаскивания
    живёт в `Canvas` (`drag`), параметры tool/rotation из `show` убраны.
- `DirtyRect`, `BORDER_PX = 1` — публичные символы, на них завязаны тесты.

## 6. Замкнутое поле (тор)

- `wrap`, `neighbors4`, `neighbors8`, `cells_in_radius` заворачивают координаты
  через край; у угловой клетки столько же соседей, сколько у любой другой.
- Дубликаты запрещены: на поле из двух клеток левый и правый сосед — одна
  клетка, она считается один раз.
- `Life::step` читает соседей только через `neighbors8` и `neighbors4`,
  поэтому белоклетка, уходящая за край, появляется с противоположной стороны.
- `cells_in_radius` и радиусы старой колонии — по тору, обрезания краем нет.
- Штамп колонии (`Sim::stamp`) заворачивает фигуру целиком.
- Оверлей радиуса конфликта дорисовывает копию круга через край (сейчас код
  оверлеев удалён вместе с `overlays.rs`; вернётся только вместе с ними).
- Исключение — `resize`: это изменение размера мира, а не движение клеток,
  содержимое центрируется и обрезается.

## 8. Тесты

### 8.1. Игра (`tests/life.rs`, 29 штук)

Классическое ядро (мишень — добыча без хищников, поэтому старые сценарии
B3/S23 остаются в силе):

- still life (блок) и мигалка;
- недо-/перенаселение: 1 сосед убивает, 4 соседей убивают, 2 и 3 — выживание;
- рождение только ровно при 3; при 2 и при 4 — не рождается;
- мигалка поперёк шва заворачивает в вертикальную у края;
- глайдер на 16×16 возвращается на место за 4×16 = 64 поколения и проходит
  через дальний край;
- `step` увеличивает поколение на пустом поле; `alive` всегда равен пересчёту;
- `clear`, `set_alive` (без двойного счёта и без ухода в минус);
- `fill` воспроизводим по seed (`ChaCha8Rng::seed_from_u64`), уважает 0.0/1.0;
- `resize` центрирует и пересчитывает `alive`;
- детекция цикла: мигалка даёт `cycle == Some(2)`, блок — `Some(1)`, пустое
  поле — `Some(1)` на первом шаге;
- любая правка (`set_alive` / `clear` / `fill` / `resize`) снимает `cycle`,
  `forget_cycles` позволяет найти тот же цикл заново;
- конечный мир всегда циклится: на поле 3×3 (3^9 состояний с учётом видов)
  цикл находится не позже чем за 19684 шагов — принцип Дирихле.

Два вида клеток:

- хищник съедает добычу в N4 и остаётся жив; одинокий хищник гибнет от голода,
  мир вымирает и циклится;
- хищник рождается только при ≥2 хищниках в N8 **и** добыче в N4 (два
  негативных случая);
- добыча не рождается рядом с хищником;
- сценарий «блок + голодный хищник»: съел → умер → блок восстановился →
  `cycle == Some(1)`;
- `set_cell` красит видом, обновляет счётчики и начинает новую историю;
- инвариант `alive == prey + predator` после шагов, `fill`, `set_cell`,
  `resize`; `fill` по одному seed даёт оба вида и воспроизводим;
- цвета `palette::PREY`/`palette::PREDATOR` равны `#000000`/`#D32F2F`.

## 9. Производительность

- Сетка — плоский `Vec<Cell>`; буфер `next` клонируется один раз на поколение.
- Не более `MAX_TICKS_PER_FRAME = 6` поколений за кадр; дробный остаток
  накапливается в `tick_accumulator`, поэтому низкий `ticks_per_second`
  всё равно продвигает игру; при перерасходе остаток сбрасывается.
- Пока игра идёт, каждый кадр запрашивает новый repaint — анимация не зависит
  от движения мыши.
- Рендер — `ColorImage` + `TextureHandle`, перерисовка только bounding box
  изменившихся клеток.
- Целевая производительность: 60 FPS на сетке ~200×100 при клетке 14 px.

## 11. Что запрещено

- Использовать `unsafe` без обоснования.
- Смешивать логику симуляции и UI в одном модуле.
- Добавлять варианты в `CellState` или убирать существующие (ломает колонию и
  её тесты); виды клеток живут в `Cell::species`, а не в `CellState`.
- Возвращать классическое правило B3/S23 как единственное или добавлять
  переключатель правил в UI.
- Подключать `Sim` и модули колонии к `App`/UI заново без отдельного решения.
- Забывать заворот через край — тор обязателен во всех подсчётах соседей.
- Вводить панели инструментов, сохранение/загрузку или параметры правила.
- Возвращать ползунки (`egui::Slider`) — числа задаются только `DragValue`.
- Заменять зум с Ctrl+колеса полями ввода, кнопками или колесом без Ctrl.
- Использовать `f64` — только `f32` для совместимости с egui (кроме
  `rng.gen_bool`, которому нужен `f64`).
- Хардкодить размеры окна и сетки — только константы и `grid_dims_for`.
- Использовать глобальное состояние (`static mut`, `lazy_static` для
  симуляции).
- Оставлять предупреждения clippy или нечитаемые имена (`i1`, `tmp`).

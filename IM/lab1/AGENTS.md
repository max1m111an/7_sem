# Промпт для ИИ-агента: клеточный автомат «Фитопланктон–Зоопланктон»

## Контекст

Ты реализуешь на Rust симулятор клеточного автомата с GUI на `eframe`/`egui`. Модель — экосистема из двух типов существ: **фитопланктон** (стационарный, ресурс) и **зоопланктон** (подвижный, потребитель). Никаких конструкций, паттернов, стресса, антиклеток, ресурсов воды/еды/энергии, глобальных режимов и прочих механик из предыдущих итераций. Только то, что описано ниже.

Работай пошагово: каркас проекта → ядро симуляции → UI → проверка. На каждом шаге проект должен собираться `cargo build`.

## 2. Поле и соседство

- Прямоугольная сетка `W × H`.
- **Тор:** выход за край заворачивает координаты (`x mod W`, `y mod H`).
- **N4(i):** 4 соседа по граням (с учётом тора). Используется для **восприятия** зоо.
- **N8(i):** 8 соседей (грани + углы, с учётом тора). Используется для **движения** зоо.
- Никаких радиусов больше 1. Всё локально.

---

## 3. Состояния клетки

Ровно три состояния:

```rust
pub enum CellState {
    Empty,
    Phyto,   // фитопланктон
    Zoo,     // зоопланктон
}
```

Никаких `Wall`, `Construction`, `Overlap`, `AntiCell`, `Citizen`.

---

## 4. Поля клетки

```rust
pub struct Cell {
    pub state: CellState,
    pub energy: f32,   // только у Zoo
}
```

- У `Phyto` и `Empty` поле `energy` не используется (равно 0).
- Возраста, стресса, таймеров, заморозки — нет.
- Фито живёт до поедания, смерти от старости нет.
- Зоо живёт, пока `energy > 0`.

---

## 5. Правила фитопланктона (Phyto)

Фито — стационарный ресурс. Он появляется **только по команде пользователя** (см. §9, инструменты UI) и **никогда не рождается сам**. Фито исчезает только при поедании зоо.

### Правила
- Фито не двигается.
- Фито не умирает от старости или перенаселения.
- Фито не размножается.
- Клетка с фито становится `Empty`, если на неё зашёл зоо (см. §6).

### Важно
Так как фито не восстанавливается сам, общее число фито на поле может только уменьшаться или пополняться вручную через UI. Это осознанное решение — колония зоо обречена на вымирание без вмешательства игрока.

---

## 6. Правила зоопланктона (Zoo)

Зоо — подвижный потребитель. Каждый тик он совершает одно действие: пытается шагнуть или остаётся на месте. Каждый тик он теряет 1 энергию на жизнь.

### 6.1. Восприятие
Перед движением зоо смотрит на **N4(i)** (4 соседа по граням, с учётом тора):
- **Есть ли `Phyto` среди N4?**
- **Есть ли `Empty` среди N4?**

### 6.2. Приоритет действия
1. **Если в N4 есть `Phyto`** — зоо шагает на **одну из таких клеток** (выбор — по фиксированному приоритету направлений: вверх → влево → вправо → вниз; первая фито в этом порядке — цель). Заход на фито = **поедание** (см. 6.3).
2. **Иначе, если в N4 есть `Empty`** — зоо шагает на **случайного пустого соседа** (равномерно среди пустых).
3. **Иначе** (все 4 соседа заняты фито, которые не первый приоритет, или другими зоо) — зоо **остаётся на месте**.

При шаге старая клетка становится `Empty`, новая — `Zoo` с тем же `energy`.

### 6.3. Поедание
Если зоо шагнул на клетку с `Phyto`:
- `Phyto` исчезает (становится `Empty`);
- `Zoo.energy += food_value` (параметр конфига);
- зоо **остаётся на этой клетке**.

### 6.4. Расход энергии
Каждый тик, независимо от того, шагнул зоо или остался, `Zoo.energy -= 1.0`.

### 6.5. Смерть от истощения
Если после всех действий `Zoo.energy <= 0`:
- клетка становится `Empty`.

Смерти от старости нет. Вероятности случайной гибели нет.

### 6.6. Размножение (почкование)
Размножение разрешено **всегда**, если хватает энергии.

Условие: `Zoo.energy >= reproduction_cost` (параметр конфига).

При выполнении:
- `Zoo.energy -= reproduction_cost`;
- в **случайном пустом N8-соседе** появляется новая `Zoo` с `energy = child_start_energy` (параметр конфига);
- если пустых N8-соседей нет — размножение не происходит.

Родитель **остаётся на месте**. Ребёнок появляется рядом. Никаких режимов `Surplus`/`Normal` — размножение всегда по одному правилу.

### 6.7. Нет стресса, нет превращений
У зоо нет стресса, нет превращения в другую сущность, нет стадий жизни.

## 7. Порядок хода

Синхронное обновление: все клетки читают старое поле, пишут новое. Буфер `next` переиспользуется через `std::mem::swap`.

Каждое поколение:

1. **Сбор намерений движения.** Каждый `Zoo` выбирает цель по §6.1–6.2 и записывает `(from, to)` в буфер.
2. **Разрешение конфликтов.** Если два зоо выбрали одну клетку — побеждает тот, у кого **меньший индекс `from`**. Остальные намерения отбрасываются (зоо остаётся на месте).
3. **Применение движения.** Для каждого валидного намерения: `next[from] = Empty`, `next[to] = Zoo(energy)`. Если `to` было `Phyto`, оно уничтожается и `energy += food_value` — это происходит в момент применения.
4. **Расход энергии на жизнь.** Все зоо в `next` теряют 1.0 (включая тех, кто не двигался).
5. **Смерть от истощения.** Все зоо с `energy <= 0` становятся `Empty`.
6. **Размножение.** Для каждого зоо с `energy >= reproduction_cost` — почкование по §6.6. Новорождённые не участвуют в этом же поколении.
7. **Проверка конца.** Если `Zoo == 0` — Game Over.

Все переходы — чистые функции от старого поля. Никакой глобальной памяти, кроме текущего поля.

## 8. Конфиг


Больше параметров нет. Никаких `p_low`, `p_high`, `c_max`, `food_birth_min`, `stress_radius` и т.п.

## 9. UI

### Окно
Заголовок: `Phyto–Zoo CA`. Размер 1280×800.
- Сверху — тулбар.
- Слева — canvas.
- Справа — параметры и статистика.
- Снизу — статус-бар.

### Тулбар (инструменты)
- Кисть `Empty`
- Кисть `Phyto`
- Кисть `Zoo`
- `Генератор колонии` — размещает N зоо и M фито случайно по полю. Параметры N и M задаются слайдерами в правой панели (см. §10).
- `Start / Pause`
- `Step` — один тик.
- `Reset` — очищает поле полностью.
- `Очистить` — то же, что Reset, если нужно разделить (можно объединить).

**Никаких Save/Load.**

### Мышь
- ЛКМ — применить активный инструмент в клетке под курсором.
- ПКМ — стереть (поставить `Empty`).
- Drag — рисовать линией (алгоритм Брезенхэма, применение инструмента к каждой клетке линии).
- Колесо — зум `cell_px` от 1 до 32.

**Постановка поверх разрешена:** рисование `Zoo` на `Phyto` заменяет фито на зоо, и наоборот. Рисование `Empty` на любую клетку удаляет её.

### Правая панель — параметры
- Слайдер `food_value` (0.0..100.0, шаг 0.5).
- Слайдер `reproduction_cost` (0.0..200.0, шаг 1.0).
- Слайдер `child_start_energy` (0.0..100.0, шаг 0.5).
- Слайдер `ticks_per_second` (1..60).
- Поле `seed` (u64) — для воспроизводимости ГСЧ, но детерминизм не критичен.
- Слайдер `generator_zoo_count` (0..1000).
- Слайдер `generator_phyto_count` (0..2000).
- Кнопка `Сгенерировать колонию` — использует значения слайдеров выше, **добавляет** к текущему полю (или заменяет — на твой выбор, но зафиксируй поведение в комментарии кода).

### Правая панель — статистика
- Поколение (число тиков).
- Число `Phyto` на поле.
- Число `Zoo` на поле.
- Средняя энергия зоо.
- Статус: `Running` / `Paused` / `Game Over`.

Никаких графиков. Никаких режимов.

### Canvas
- Отрисовка через одну текстуру `ColorImage` размером `W*cell_px × H*cell_px`.
- Перерисовка только изменённых клеток.
- Палитра:

| Состояние | Цвет заливки | RGB |
|---|---|---|
| Empty | тёмно-серый | `#1E1E1E` |
| Phyto | зелёный | `#2ECC40` |
| Zoo | чёрный | `#000000` |

- **Грани всех клеток — чёрные** (`#000000`), толщина `border_px`. При `cell_px == 1` грани не рисуются.

### Оверлеи
- Нет. Никаких тепловых карт, стресса, энергии на экране.
- Опционально: можно показывать энергию зоо оттенком чёрного (например, чем темнее — тем больше энергии), но это **не обязательно** и не должно быть по умолчанию.

## 10. Что запрещено

- Использовать `unsafe` без обоснования.
- Смешивать логику `sim` и `ui` в одном модуле.
- Добавлять стресс, антиклетки, конструкции, паттерны, заморозку, `Overlap`, ресурсы, режимы питания, глобальные уровни.
- Добавлять фито, которое рождается само, размножается или умирает от старости.
- Добавлять зоо, которое двигается не по правилам §6.
- Добавлять движение зоо в N8 — движение **только по N4**, восприятие **только по N4**.
- Хардкодить параметры в правилах — только через `SimConfig`.
- Использовать `f64` — только `f32` для совместимости с egui.
- Глобальное мутабельное состояние (`static mut`, `lazy_static` для симуляции).

## 13. Что важно понять

- Это **чистый клеточный автомат**: только локальные правила, синхронное обновление, тор.
- **Фито — стационарный ресурс**, который игрок ставит вручную. Он не восстанавливается, не размножается, не умирает сам.
- **Зоо — единственный агент движения.** Он видит N4, двигается N4, ест при заходе на фито, платит 1 энергию за жизнь, размножается, когда накопил достаточно.
- **Нет глобального уровня питания.** Нет `P`, нет режимов `Famine`/`Normal`/`Surplus`. Число фито на поле влияет на колонию только косвенно — через то, сколько зоо сможет поесть.
- **Нет стресса.** Зоо умирает только от истощения.
- **Нет победы.** Есть только Game Over при исчезновении зоо.

Если все критерии готовности выполнены — спецификация реализована корректно.
